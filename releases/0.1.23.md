# Scholia Reader 0.1.23 — Collision-free identity and safe settings migration

## Identity

- This repository's plugin is now **Scholia Reader**, ID **`scholia-reader`**, by [ianmoran11](https://github.com/ianmoran11). Repository: [ianmoran11/obsidian-scholia](https://github.com/ianmoran11/obsidian-scholia).
- The community-store **Scholia** by shashanyu is a different, desktop-only plugin. Never force its mobile compatibility or use it to install this project.
- Scholia Reader remains desktop/mobile-compatible with minimum Obsidian **1.5.0**. Plugin and separate Pi bridge packages are versioned **0.1.23**.

## Upgrade with BRAT — keep the old data until verified

1. Back up the vault and old `<configDir>/plugins/scholia/` folder, including `data.json` and its credentials. Disable old **Scholia**, but **do not uninstall it yet**.
2. Run BRAT's **Plugins: Choose a single plugin to reinstall**, select `ianmoran11/obsidian-scholia`, and install latest **0.1.23**. Unpin an older version if needed. An ordinary update may fail after the ID change, especially on Android; reinstall writes the new ID's folder. BRAT itself does not copy or migrate settings.
3. Enable **Scholia Reader**. With no existing new saved data, it checks the legacy manifest before reading settings, then saves recognized, correctly typed settings (including API and bridge tokens) under the new plugin ID. It supports custom Obsidian configuration directories and never changes old files.
4. Verify the copy-success notice, settings, credentials, templates and capture destination. Reassign hotkeys/mobile toolbar bindings as necessary because command IDs now use `scholia-reader:`. The migration copies plugin settings only; it does not change Obsidian's hotkeys, toolbar bindings or enabled-plugin list.
5. Keep old Scholia disabled. Only after verification, optionally uninstall the old copy and retain your backup.

Fresh installs: add the same repository in BRAT and enable **Scholia Reader**. BRAT installs only the Obsidian plugin; the [Pi bridge setup](https://github.com/ianmoran11/obsidian-scholia/blob/0.1.23/bridge/README.md) remains separate.

## Safety and preservation

- Existing new settings, even an empty object, are never overwritten by migration.
- Foreign/unverified manifests, empty/unrecognized data and read/parse/save failures do not trigger an accepted import. Keep the old files and follow the retry notice: fix the source, then disable/re-enable Scholia Reader before changing new settings. Migration does not save defaults that would prevent a later retry.
- No plugin is automatically disabled or uninstalled. No credentials or settings are logged by migration.
- Notes, templates, CSS callout names (`scholia*`), default `scholia/` paths and existing run snapshots are unchanged.

## Validation

288 plugin tests and 16 bridge tests pass, along with both TypeScript checks and production builds. Migration tests cover source identity, typed settings and token preservation, custom configuration directories, existing new data, retryable failures, unload during asynchronous operations and untouched legacy files. Release checks enforce plugin identity and mobile compatibility. Live Obsidian/BRAT desktop and Android migration has not been device-tested; follow the upgrade steps above and verify copied settings before removing the old installation.
