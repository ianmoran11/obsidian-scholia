# Scholia Reader 0.1.24 — Fresh template models after edits

## Fixes

- Template commands now read and validate the current template YAML on every run. Removing an OpenRouter `model` override really uses the current Pi model setting, even when template hot reload is disabled, missed, or a previously registered command is retained.
- Hot reload detects edits when Obsidian mutates the same file object. Fresh YAML and prompt text are read together instead of trusting potentially stale metadata-cache frontmatter. Command IDs, names, and hotkey registration behavior are preserved.
- Missing, unreadable, or invalid templates stop safely rather than using cached configuration. Source editor/note changes during preparation, template changes during its read, and plugin unload prevent generation from starting. Read-error notices do not expose file contents or underlying errors.
- Mobile selections are preserved across the fresh template read. Regeneration also rejects templates that are deleted, renamed or modified during that read.
- Model notices distinguish invalid default settings, incompatible template overrides, and incompatible old callout snapshots. Valid explicit overrides remain enforced; there is no silent model remapping or paid OpenRouter fallback.

## Pi users

With **Pi** selected in Scholia Reader settings, remove the template's `model:` override to use the **Pi model** setting, such as `openai-codex/gpt-5.5`. An explicit template override must use the selected backend's model format. Model availability still depends on your separately configured Pi bridge/account.

Existing callouts keep their original model/backend snapshot. Editing the template does not rewrite old snapshots: restore the original backend to regenerate, or **run the template anew** to use the current model settings.

## Upgrade and compatibility

Update `ianmoran11/obsidian-scholia` in BRAT. The plugin remains **Scholia Reader**, ID **`scholia-reader`**, mobile-compatible (`isDesktopOnly: false`), requiring Obsidian **1.5.0+**. Plugin and separate bridge packages are versioned **0.1.24**; BRAT installs only the plugin. If upgrading from the old `scholia` ID, retain backups and follow the [identity migration instructions](https://github.com/ianmoran11/obsidian-scholia/releases/tag/0.1.23).

## Validation and limitations

Regression tests exercise actual registered callbacks with the same mutable file object and stale metadata cache, along with refresh, errors, unload/editor races, provider enforcement, and old snapshot regeneration. All 328 plugin tests and 16 bridge tests pass, along with both TypeScript checks, builds, and release validation. No Android/desktop Obsidian device check or live model/provider call was performed; `gpt-5.5` availability is not certified by this release. No user vault, authentication, or service configuration was changed.
